## 目标与原则

目标是让最终返回的上下文包含回答问题所需、且保留适用条件的原文证据。错误标签会制造误召回，过严的过滤会制造漏召回，二者都不能靠多填字段解决。

1. 忠实记录原文说了什么，不凭常识补案例事实，不把作者观点改写成普遍真理。
2. 保留多对象、多案例、多主题，用对象与语境绑定防止串配，不为单值字段拆坏完整论述。
3. 原文陈述、确定性派生、校勘建议分别保存；无法确定时保留证据和原因。
4. 标签默认用于补充候选和排序。明确的用户限制才用于严格筛选；保留不依赖这些标签的正文检索通道，让通用知识和缺标签材料仍有被找回的机会。
5. 用相同问题、检索预算及上下文预算比较最终证据覆盖；Schema 通过、标签变多和模型自评均不证明质量提高。

下文字段已由当前Schema与新写校验入口支持。旧记录仍走历史读取边界，不能用历史模型构造成功代替新写校验。仓库落实路径与验证见 `docs/architecture/annotation-implementation-2026-10-13.md`；仅持有dots包时，执行依据为包根目录的 `rules/CONTRACT.md` 与 `PREPARATION_REVIEW.md`，不需要访问仓库外部文档。

## 共用语义与记录方式

**提及**是术语出现在原文中；**讨论**是对概念有实质说明；**实际使用**是方法或对象被用于明确的分析，分析可以是案例或假设演示。三者不能互相推定。介绍完整度独立于是否使用。

**原文陈述**是可以定位到作者文字的主张；**确定性派生**是依据已知输入和版本化规则计算的信息；**校勘建议**是对疑点的判断。语境至少区分概念说明、一般规则、条件/假设、具体案例；否定是独立属性，不与这些语境互斥。

未来 S5 在现有 `S5_annotation.json` 报告中增加逐字段证据记录，S6 复核。记录包含新 chunk_id、字段路径/对象、原句和位置、案例/规则范围、否定/条件、取值依据及 null 原因。新04正文偏移与 lineage 可定位回原输入；重叠段共用同一原始证据，不计为新增独立事实。修订3的机器校验读取S5主报告中的完整field_evidence；额外附件可作说明，但不能替代主报告的逐块证据数组。

null 原因区分 `not_mentioned`、`not_applicable`、`ambiguous`、`multiple_values`（旧单值投影无法无损表达）。明确否定是 false，不是 null。多值实体集合没有提及项时为空集合，不造“未知实体”；原因放在过程记录中。

扁平检索标签由证据聚合，不能反过来证明对象关系。需要绑定的值保留在同一结构记录；严格关系匹配不能用两个无绑定数组的交集代替。

## D02：西占盘类

新增多值 `chart_types_mentioned` 承接明确提及的盘类，在证据中区分提及、讨论和应用。沿用词表十类：本命盘、合盘、行运盘、组合盘、太阳回归盘、月亮回归盘、推运盘、卜卦盘、择日盘、世俗盘。通用行星象征段不自动标为全部十类。

`chart_type` 保留为 nullable 的兼容主类：仅有一个实质讨论/应用的盘类，或原文明示主类时填；多类并列无主次则 null/multiple_values。纯概念段 null/not_applicable，案例盘类未说明则 null/not_mentioned。章节可提供明确上下文，但必须记录出处，不能越过案例或章节边界继承。

“比较本命盘与行运盘”保留两类及比较关系；“水星象征交流”不补本命盘。检索合并具体盘类与通用正文候选后排序；显式“只要行运盘案例”才严格满足该限制，未知盘类不能冒充匹配。

实现已取消Schema和PayloadProjector的非空要求并增加多值投影；旧顶层western_chart_type保留canonical兼容值，嵌套字段使用term_id。严格筛选使用带证据的semantic_facts；未核验或修改线上过滤与数据库。

## D03：紫微三个遗漏概念

三个概念均保留，进入 YAML 后由 Registry 消费，不在校验器复制枚举：

- 多值 `chart_types_mentioned` 采用原确认表五类：本命盘、合盘、大限盘、流年盘、流月盘；`chart_type` 按 D02 规则作兼容主类。
- 多值 `relationship_types_mentioned`：夫妻、亲子、兄弟、朋友、商业、上下级，绑定关系分析。出现夫妻宫不能推出夫妻合盘，单盘谈婚姻也不等于合盘。
- 多值 `comparison_methods`：宫位对照、四化交叉、主星配对、夫妻宫互参、大限同步，区分介绍与实际使用。

后两类适用于明确讨论/应用双方关系分析的语境，不机械要求旧单值盘类等于合盘。不同双方、案例的关系与方法不做笛卡尔组合。仅列出关系类型或方法名称时可记录提及，不能推定实际采用。

盘类与时间维度相关但不能独立填两套矛盾事实。明确大限盘可按固定映射派生大限时间标签并注明派生；只提大限不能反推大限盘或实际使用。婚姻主题与关系分析类型按 D11 分开。

## D04：马头带剑与马头带箭

当前 YAML 的“剑”为“擎羊在午宫坐守”，“箭”为“天马与擎羊同宫或天马与火星同宫”。这说明当前来源定义不同，不能据此断言所有门派都认为它们不同。

裁定保留两个来源概念，实施时分别用 `pat_horse_head_sword`、`pat_horse_head_arrow`。两者不互为无条件别名；共享拼音作为歧义表达保留相关候选，精确中文名称优先命中对应项。

旧 `pat_matou_daijian` 退为存在冲突的旧标识，不指定全局继承者。只有旧 canonical、原文条件、来源路径或可验证版本足以消歧时才映射；只有旧 ID 时保留 legacy ambiguous，不静默归一。旧 ID 查询可返回两组消歧候选，不能宣称等价。今后若有门派同义证据，记录带来源的对应关系，不抹去旧定义。

实现已检查ID唯一性、登记需证据消歧的迁移并升级词表；旧标注和数据库保持不动。

## D05–D06：塔罗牌阵

`spreads_mentioned` 保留明确提及的固定牌阵。新增多值 `spreads_used` 记录明确用于一次分析的牌阵并按案例绑定；旧 `spread_used` 仅投影唯一/明确主要用阵，多例多阵不强选。名称来自明确上下文时记录出处并纳入 mentioned 集合。

介绍完整度按牌阵记 complete/partial/not_explained/unknown，与实际使用独立。“本次采用凯尔特十字，先看前三个位置”可标使用、介绍partial；“下一章介绍凯尔特十字”只有提及；假设演示用阵保留 hypothetical，不能冒充真实占例。

“无牌阵”从“三张牌阵”的无条件别名中移除，作为无固定布局的组织方式。布局状态与原文抽牌数分开，数量未知不猜。三张牌可没有固定布局；仅有三张牌不能判三张牌阵。须明确命名或具有可唯一识别、经词表定义的固定布局；过去/现在/未来三词共现不能证明用阵。

旧映射记为有损历史归一化，未来迁移回到原文核对，不全库机械反替换。

## D07–D09：六爻

**D07**：兼容 `yong_shen` 统一表示取用的六亲类别，不能填原神/忌神等角色。权威表达改为逐对象角色记录：角色（沿用受控角色表）、六亲（沿用六亲表）、爻序数（若有）、语境与证据。同一对象在不同规则中可承担不同角色。

“以妻财为用神”记录用神角色、妻财类别、爻位未知；“二爻妻财为用神”才绑定2；“忌神发动”记录忌神及动的条件/陈述，六亲和爻位未知。不根据求财问题补妻财为用神，不把世爻等位置角色与六亲混成同一枚举。多个用神无法单值表达时，兼容值null并保留结构多值。

**D08**：分开爻序数1–6、阴阳属性，阴阳允许null，保留原始surface；旧 `position` 退为兼容表达。“二爻”→2/未知，“九二”→2/阳，“六二”→2/阴，“上六”→6/阴。完整映射由统一规则生成和验证。不同卦或案例的同序数爻不是同一对象；动静按D01判断。

**D09**：卦宫 canonical 统一为乾宫、兑宫、离宫、震宫、巽宫、坎宫、艮宫、坤宫。“乾”只有在卦宫字段语境可归一乾宫，不能把八卦名到处扩成卦宫。

原文明示才写来源陈述；只有卦名时允许版本化词表查表，单列 derived 值、规则版本和输入，不冒充作者陈述。作者归宫与词表不一致则两者分别保存并记录差异。派生标签可补候选，不能证明原文确有该陈述。

## D10：摘要

普通标注中文 `summary` 上限300个 Unicode code point，含标点空白；英文 `summary_en` 上限150个按空白分隔的非空词，连字符词算一词。双语要求保持。该长度是本次选定的初始合同，尚未证明为检索最优值。

短文不扩写凑长度；长段保留主体、论断、条件、否定与例外，精简背景。中英文含义一致，英文采用受控术语，不堆别名。超限重写并核对事实，不用字符串切片截尾；完整 chunk_text 保留，不以摘要替代正文。

旧处理器曾把两种摘要都截到300字符、审核器另有150字符限制；现已取消截断，并统一生成、Schema、审核、导出及包工具。英文摘要保留特定英文检索/重排路径，相关检索测试已纳入本轮检查。CardCombinationChunkV2 没有普通摘要，本决策不向它强加字段。

## D11：主题、知识领域、方法

- 问题主题：涉及什么生活问题/诉求，如婚姻、事业；采用流派自己的受控主题、多值表达。
- 知识领域：解释哪类专业知识，如星曜性质、爻位；沿用各派分类并允许多值，不为数量整齐统一分类。
- 分析方法：如何分析，与前两轴分别记录；取用神方法不等于求财主题。

以各派 `topics_mentioned`、`knowledge_domains` 的多值语义为准；已有 `question_type`、`reading_topic`、`analysis_type_mentioned` 按真实含义归轴，混合项显式拆分，不能按字段名互拷。仅语义等价时建立跨派主题映射，不强行对齐不同门派的知识分类。

顶层 `topic`、旧单值 `knowledge_domain` 仅兼容主类：唯一/明确主要项时投影，否则null，不独立再标一遍。主题用于扩展/排序，知识领域用于组织及有依据的路由；保留现有 knowledge_domains 不进入 BM25 术语注册的边界。

新增标签不自动成为硬过滤条件。纯讲专业机制而没有生活主题时，主题为空并注明不适用。未收录但有证据的概念保留原词和注册候选，不塞进不相干canonical；实施时按本授权原则裁定，无需回到逐项索要用户同意。

## D12：证据、语义样例与最终效果

属性只绑定被说明的对象，扩大范围须有全称表述或明确共指。“水星逆行，金星在二宫”不能给金星标逆行；“世爻发动”不能标成二爻动，除非原文明确世爻就是二爻。四化、正逆位、时间层级、双方盘归属同理。

条件、否定、对照和例外与结论一起保留到切块与摘要；跨块需要可定位上下文，不能从未知连续碎片拼事实。原文与词表存在命理观点差异时保留作者陈述、来源和差异记录；词表控制名称，不替作者改观点。

冲突旧示例退出语义金标。实施时每项覆盖正例、明确反例、未声明、不适用、条件句、多实体/案例；预期值由具体原句确定，不能用旧标签或同次模型输出作标准答案。结构校验与语义复核分报。

效果分两组比较：固定正文/边界比较旧标注与新标注，再比较完整旧流程与新清理/切块/标注流程，避免混淆改善来源。全流程按原始证据片段对齐，不按会变化的chunk_id判断命中。

离线题集分别覆盖四派的术语/别名、通用知识、案例、多实体关系、条件否定、未知标签、中英文查询；同一来源的近重复及派生材料归组，调规则样例与最终测试组分开。固定检索器、模型和预算，报告候选 Evidence Recall@25、最终 Evidence Recall@5、nDCG@5、错误对象/关系/条件命中率及固定上下文token预算内的证据覆盖。25/5来自当前默认值，正式评估随实际配置记录，不能仅扩大新流程预算。

去重后四派分别报告，再给宏平均、分组差异和不确定区间，避免紫微大样本掩盖其他派退化。召回上升若伴随错误证据增加，不能直接宣布更好，须复核对应规则。提升幅度由实测确定；本轮未生成金标、调用模型或运行检索评测。

## D13：无名称的结构化关系

保留命名组合枚举；夹辅、对宫等无独立canonical的规则使用独立关系记录：关系类型、参与对象及角色、宫位/爻位、语境、条件/否定、证据。关系类型登记到 YAML 后由 Registry 生成约束，不从effect/description发明名称。

作者明确说A、B夹某宫可记夹辅对象和目标宫；只出现三者不能认定夹辅。一般规则不伪造成真实命盘。吉凶效果保留条件与作者归属，不广播给所有同现对象。

检索先以关系类型/实体补候选，再验证同一关系记录的角色和条件。若生产投影采用对象数组，关系筛选需按同一对象/记录嵌套匹配，不能从不同记录各取一项拼成成立关系。不要求先建图数据库，结构化payload与重排检查可作为实施起点。
